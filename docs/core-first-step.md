# First Rust core increment

Original, dependency-free Rust library: `crates/cam-core`.

## Run locally

Requires Rust with edition 2024 support, Cargo, and a native linker.
Validated with Rust 1.99.1 on Windows.

```text
cargo test --offline --workspace
cargo clippy --offline --workspace --all-targets -- -D warnings
cargo fmt --all -- --check
```

## Executable demo

```text
cargo run --offline --example facing
cargo run --offline --example facing -- 120 80 12 2 10 1 4
cargo run --offline --example facing -- --help
```

Optional arguments are width, length, height, removal depth, tool diameter,
maximum stepdown and maximum row spacing, all in mm. Provide all seven or none.
The demo uses a tool with 20 mm cutting length, 800 mm/min cutting feed,
200 mm/min plunge feed and clearance 5 mm above stock. The report contains
counts, the required start position and CSV move rows. It is not G-code.
Invalid input returns a nonzero exit status without printing a partial path.

## Show calculated paths in the prototype

### Live local calculation

Run `cargo run --locked --offline --example preview_server` and open the printed
`http://127.0.0.1:PORT/` URL. Click **Live-Planfräsen** or **Berechnen**. Enter the
seven dimensions/steps and calculate. The response comes from Rust, replaces
the displayed stock/path and uses the existing playback controls. **Abbrechen**
invalidates the result in the browser and signals cooperative cancellation.
The tool/feed defaults are the same as the CLI example, not machine settings.

The server uses an ephemeral loopback port, serves only its embedded page,
rejects foreign Host/Origin values on calculation requests, caps request sizes
and connections, and does not write files or connect to CNC equipment. It is
a small local demo bridge, not a production HTTP framework. Stop it with Ctrl+C.
The UI does not block while awaiting the request; path drawing still happens
in the browser. A standalone file opened without this server has only import
and demo functionality, not live calculation.

HTTP integration checks: `node prototype/live-server-tests.cjs URL` against the
printed local URL. These cover successful generation, invalid depth, rejected
missing/foreign origins, wrong host and the cancellation endpoint. They do not
measure cancel latency or certify browser rendering.

### File interchange

Open `prototype/fertigungsstudio-kacheln.html` and select **Rust-Demo**.
The embedded `rust-facing-demo.json` was generated by the Rust example using
`--json`. It shows rectangular raw stock, not the old illustrative pocketed part.
Use **Rust-Bahn laden** to select another JSON file produced by the same example.
`--json` must precede the seven optional numeric arguments.

The bridge is a file interchange, not live browser-side Rust or a CAD import.
Parameter edits do not regenerate imported paths. Use the Rust program to
calculate another file. The browser validates format, bounded coordinates,
motion count and some clearance rules; this is not collision verification.
For more than 5,000 moves only the first 5,000 segments are drawn, with a visible
notice; playback follows the full move list. The stock remains an uncut block.
Rebuild the self-contained HTML with `node prototype/build-ribbon.cjs`.
Run `node prototype/core-path-tests.cjs` for the interchange validation checks.
Automated browser rendering has not been verified in this environment.

## Contract

All coordinates are work coordinates in millimetres, with a fixed upright +Z
tool axis. Feed is mm/min. Language and UI are not part of this crate.
`face(Setup, FlatTool, Facing)` returns moves and an explicit required start
position. The caller must establish that position; no safe arrival from an
unknown machine state is implied.

This slice faces the entire top of an axis-aligned rectangular raw block with
a flat centre-cutting cylindrical tool. X passes run in one direction; row
spacing is at most half the tool diameter. Each row descends outside the block,
cuts across it, then retracts vertically outside the block before traversing
to the next row. The final depth is explicit, with bounded intermediate passes.
There is no climb/conventional selector or cutter-engagement optimisation yet.

Coordinates, stock bounds, feeds, tool geometry, cutting length, depths, step
sizes and the move budget are checked before path allocation. Errors are
stable enum variants for a future translated UI. Production code forbids
unsafe and denies unwrap/expect/panic; test assertions may panic.

## Evidence and limits

### Cooperative cancellation

`face_with_cancel` accepts a fast `FnMut() -> bool` callback. It checks before
allocation, once before each four-move row, and before returning the result.
An abort returns `Error::Cancelled` and drops the incomplete path. A GUI worker
can check a shared atomic flag without introducing a GUI dependency into core.
`face` remains the same API and delegates with cancellation disabled.
Cancellation does not stop an executing machine and has no hard real-time
latency guarantee. The calling application still needs worker scheduling and
must handle a cancel request that arrives after result delivery.

Tests check an analytic 20 × 10 × 5 block, final depth and row positions,
grid-point footprint coverage, work-coordinate translation, clearance on
lateral rapids and rejection of invalid/unbounded inputs.

This is a restricted planner, not a collision verifier: no CAD/STEP import,
part preservation, islands, clamps, fixtures, holder, machine travel, spindle,
stock-removal simulation, G-code generation, UI integration, persistence or
3+2 kinematics. Space outside the raw block is assumed free. No machine has
executed this output. The HTML preview still uses illustrative paths.
